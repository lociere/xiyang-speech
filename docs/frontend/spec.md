# 前端功能规格

> 范围：昔阳方言语音工具的 Web 前端。本文定义「做什么、给谁用、边界在哪」，不涉及具体实现步骤（见 `plan.md`）与验收方法（见 `validation.md`）。

## 1. 概述

前端是一个由 FastAPI 托管的单页应用，面向本地使用者，提供三项能力：

1. **方言识别**：上传昔阳话音频，返回文字，支持复制。
2. **方言合成**：输入文字，生成昔阳话语音，支持播放与下载。
3. **图片说话**（后续）：上传一张图片与文字，让图中人物开口说方言，嘴型与语音对齐，产出视频。

浏览器只访问应用层（`http://localhost:8000`）这一个源；应用层用 HTTP 反代到各推理 worker，前端永远不直接访问 worker 端口，从而避免跨域与端口暴露。

## 2. 目标与非目标

### 2.1 目标

- 一个单页 Web 界面完成识别、合成两类日常操作，界面简单直接。
- 为后续「图片说话」预留统一的异步任务交互，接入时不需要重写前端。
- 保持项目既定约束：无 Node.js、无前端构建、无 CDN 依赖，由 FastAPI 托管静态文件。

### 2.2 非目标（本次不做）

- 不实现说话人模型的推理本身（这是第三个 worker，见 `plan.md`）。
- 不做用户登录、账号、鉴权与多用户隔离。
- 不做历史记录持久化（刷新后不保留结果）。
- 不做移动端专项适配，以桌面浏览器为准。
- 不做识别/合成的实时流式（streaming）展示。

## 3. 用户故事

- 作为使用者，我想上传一段昔阳话录音，看到识别出的文字并一键复制，以便转写存档。
- 作为使用者，我想输入一句文字，生成昔阳话语音并试听、下载。
- 作为使用者，我想在上传前就能看到文件是否合法、当前各服务是否在线，避免盲目等待。
- 作为使用者（后续），我想上传一张人物图片并输入方言文字，得到人物开口说话、口型对齐的视频。

## 4. 功能需求

### FR-1 服务状态

- 页面顶部显示 ASR、TTS、说话人三个服务的在线状态（绿=在线、红=离线）。
- 状态通过应用层 `/api/health` 获取；该接口只探测，不触发模型加载。

### FR-2 方言识别

- 支持点击或拖拽上传音频，限制扩展名 `.wav / .mp3 / .m4a / .flac`。
- 上传并提交后展示识别文字，提供「复制」按钮。
- 空文件、格式非法、识别为空、服务失败时给出明确提示（对应 HTTP 400 / 422 / 500）。

### FR-3 方言合成

- 文本输入框，长度 1–300 字（与服务端 `SynthesisRequest` 一致）。
- 生成后提供音频播放器与「下载」按钮。
- 空输入、超长、服务失败时给出明确提示。

### FR-4 图片说话（后续，先做占位）

- 支持上传一张图片（`.jpg / .png`）并预览。
- 输入方言文字（或复用「合成」刚生成的音频作为音频源）。
- 提交后创建异步任务，页面展示进度条；完成后提供视频播放器与「下载」。
- 在说话人 worker 尚未接入时，提供 mock 模式返回示例视频，保证交互可先联调。

### FR-5 通用交互

- 所有同步请求有加载态，避免重复提交；失败展示可读错误，不白屏。
- 复制、下载等操作给成功反馈。

## 5. 非功能需求

| 项 | 要求 |
|---|---|
| 依赖 | 零 Node.js、零构建、零 CDN；原生 ES modules + 手写 CSS |
| 访问源 | 前端仅访问 `:8000`，由应用层反代到 worker |
| 性能 | 同步接口（识别/合成）单句在几秒内，前端用全局加载态覆盖等待 |
| 长任务 | 说话人视频生成走异步 job + 轮询，不用同步阻塞 HTTP |
| 兼容 | 现代桌面浏览器（Chrome / Edge / Firefox） |
| 失败体验 | 网络错误、服务离线、业务校验失败均有明确中文提示 |

## 6. 约束与假设

- 后端为 FastAPI，Python 3.10；`httpx`、`python-multipart` 已在依赖中。
- 运行环境 WSL2 Ubuntu + NVIDIA GPU；6GB 显存下模型串行调用，不同时常驻两个模型。
- 国内网络环境下不依赖任何外部 CDN 或在线字体/图标库。
- 端口约定：应用 `8000`、ASR `8101`、TTS `8102`、说话人 `8103`（预留）。

## 7. API 契约

前端实现以此为对接标准；应用层负责把请求转发到对应 worker。

### 7.1 健康检查

- `GET /health`：保留现状，后续把 `speech_api_ready` 升级为 `true`。
- `GET /api/health`：

```json
{"asr": true, "tts": true, "talk": false}
```

`talk` 为 `false` 表示说话人 worker 未接入，前端对应显示「离线」或「即将上线」。

### 7.2 识别

- `POST /api/asr/recognize`
- 请求：`multipart/form-data`，字段 `audio`（文件）。
- 成功 `200`：`{"text": "识别出的文字"}`。
- 错误：`400`（格式非法/空文件）、`422`（无文字）、`500`（识别失败）。

### 7.3 合成

- `POST /api/tts/synthesize`
- 请求：`application/json`，`{"text": "..."}`。
- 成功 `200`：`audio/wav` 二进制流，附件名 `xiyang_speech.wav`。
- 错误：`400`（空输入）、`422`（超长，按 pydantic 校验）、`500`（生成失败）。

### 7.4 图片说话（预留）

- `POST /api/talk`
- 请求：`multipart/form-data`，二选一：
  - 字段 `image`（文件）+ `text`（字符串，走「TTS 生成音频 → 说话人」链路）；
  - 字段 `image`（文件）+ `audio`（文件，直接以该音频驱动口型）。
- 成功 `202`：`{"job_id": "<uuid>"}`。
- `GET /api/talk/{job_id}`：

```json
{"status": "queued|running|done|error", "progress": 0, "video_url": null}
```

- `done` 时 `progress=100`，`video_url` 指向可播放的视频；`error` 时附错误说明字段。
- 前端在 `api.js` 中封装 `submitJob()` + `pollJob()`，识别/合成也可复用同一套「提交 + 查询」抽象（当前识别/合成为同步直返）。

## 8. 界面结构

单页三卡 + 顶部状态栏：

- **顶部**：项目名 + 三个服务状态点。
- **识别卡**：上传区（点击/拖拽）→ 识别按钮 → 结果文本框 + 复制。
- **合成卡**：文本输入 + 字数提示 → 生成按钮 → 音频播放器 + 下载。
- **说话人卡**：图片上传预览 + 文本输入（或选择复用音频）→ 生成按钮 → 进度条 → 视频播放器 + 下载。

## 9. 术语

| 词 | 含义 |
|---|---|
| 应用层 | 端口 8000 的 FastAPI 进程，托管前端并反代到 worker |
| worker | 独立推理进程（ASR / TTS / 说话人），各自有模型与端口 |
| 说话人 | 「图片人物开口说话、口型对齐」能力及其 worker |
| job | 异步任务，用 `job_id` 提交与轮询结果 |
